# MinecraftLinuxUtils

Bash-утилиты для серверов Minecraft на Linux.

Проверялось на Ubuntu 24.04 и 26.04 LTS с Java 25. На Debian работает так же.
Версии Minecraft 26.x требуют Java 25, на Java 21 они не стартуют.

## Что где

| Файл | Зачем |
|---|---|
| `mc-jar.sh` | Качает Paper или Velocity в общий каталог, раскладывает симлинки по серверам |
| `start.sh` | Запуск одного сервера с автоперезапуском. Кидать в папку сервера |
| `mcstart.sh` | Поднимает все сервера из `servers.conf` в окнах одной сессии tmux |
| `restart.sh` | Перезапуск всех серверов с предупреждением игроков. Для cron |
| `backup.sh` | Бэкап с `save-off` и `save-all`, режимы tar и restic |
| `ms.sh` | Переключение версий на одной папке через симлинки |
| `collect-audit.sh` | Срез системы для разбора инцидента. Только чтение |
| `ssh-notify.sh` | Уведомление в Telegram при входе по SSH, через PAM |
| `systemd/paper@.service` | Шаблонный юнит, один на все сервера |
| `newLogic/start.sh` | Общий скрипт запуска для нескольких серверов с тонкими обертками |
| `newLogic/updater.sh` | Обертка над `mc-jar.sh` с интерфейсом `updater.sh <версия>` |
| `example/` | Готовая раскладка папок и конфигов, с которой все это работает как есть |

Конфиги: `servers.conf`, `backup-exclude.conf`, `ssh-notify.conf`. В репозитории лежат
только `.example`, свои копии в git не попадают, за этим следит `.gitignore`.

Если разворачиваете с нуля - начните с [example/](example/), там связка из прокси
и двух серверов Paper с расставленными портами и готовым списком исключений бэкапа.

## Быстрый старт

```bash
git clone https://github.com/BrainRTP/MinecraftLinuxUtils.git ~/scripts && cd ~/scripts
chmod +x *.sh newLogic/*.sh
sudo apt install tmux curl jq

cp servers.conf.example servers.conf   # поправить пути
sudo mkdir -p /opt/mc/jars && sudo chown "$USER" /opt/mc/jars

./mc-jar.sh paper 26.2 /home/mc/mainServer
cp start.sh /home/mc/mainServer/       # поправить JAR, MIN_RAM, MAX_RAM
./mcstart.sh
tmux attach -t minecraft
```

## Один jar на несколько серверов

`mc-jar.sh` кладет ядро в общий каталог (по умолчанию `/opt/mc/jars`) и ставит в папку
каждого сервера симлинк с именем вида `mainServer-paper.jar`. Имя сервера в названии
нужно затем, чтобы в `ps auxfww` было сразу видно, какой процесс кому принадлежит.

Смысл не в экономии места: 30 мегабайт на пять серверов ничего не решают.
Смысл в атомарности. Обновили один файл - все сервера на следующем рестарте
поднялись на одинаковом билде. Без этого через полгода половина серверов
на одной сборке, половина на других, и ловится баг, который воспроизводится через раз.

Скрипт сверяет sha256 из ответа API и не качает то, что уже лежит. По умолчанию берет
только сборки канала `STABLE`, для остальных нужен `MC_ALLOW_EXPERIMENTAL=1`.
Старые сборки чистятся, три последние остаются, файлы под симлинками не трогаются.

## Запуск

Три способа, выбирать по ситуации.

**tmux плюс `start.sh`** - когда нужна живая консоль. Java крутится на переднем плане,
команды вводятся руками. Ctrl+C во время обратного отсчета выходит из цикла перезапуска.

**systemd плюс `paper@.service`** - когда нужен автозапуск после перезагрузки машины.
Консоли при этом нет, команды шлются через RCON. В юните прописаны ограничения
`NoNewPrivileges`, `ProtectSystem=strict` и `PrivateTmp`.

**`newLogic/start.sh`** - когда серверов несколько и хочется одну точку правки.
Общий скрипт лежит в одном экземпляре, у каждого сервера тонкая обертка:

```bash
#!/bin/bash
bash "$HOME/scripts/newLogic/start.sh" paper MainServer "$HOME/mainServer" 180 20 -Xms4G -Xmx4G
```

Версия ядра берется из файла `version` в папке сервера.

## Бэкапы

`backup.sh` перед архивацией шлет серверу `save-off` и `save-all flush`, после -
`save-on`. Без этого сервер продолжает писать мир на диск во время копирования,
и архив выходит битым.

Перед `tar` скрипт сравнивает свободное место с размером данных и пропускает сервер,
если места не хватает. Готовый архив проверяется через `tar -tzf`: битый лучше
заметить сразу, а не через полгода.

Что не тащить в копию, задается двумя файлами: `backup-exclude.conf` рядом со скриптом
действует на все сервера, а `.backupignore` в папке сервера - только на него.
Один шаблон в строке, `#` и пустые строки игнорируются.

Режим `tar` кладет архивы локально, `restic` отправляет в S3 или по SFTP с шифрованием
на стороне клиента и дедупликацией. Копия на той же машине спасет от кривого обновления
плагина, но не от смерти диска. Выносите наружу.

## Уведомления в Telegram

`ssh-notify.sh` вешается через `pam_exec`, а не через `/etc/profile.d`. Разница в том,
что хук на `profile.d` срабатывает только при запуске интерактивной оболочки и молчит
при SFTP и при `ssh сервер команда`. PAM ловит любой вход.

```
session optional pam_exec.so seteuid /usr/local/bin/ssh-notify
```

Токен лежит в `/etc/ssh-notify.conf` с правами 600, а не в теле скрипта. Скрипт всегда
возвращает 0: ненулевой код из `pam_exec` способен заблокировать вход на сервер.

Если вход только по ключу, такое уведомление почти не шумит - успешные входы редки.

## Разбор инцидента

`collect-audit.sh` собирает срез системы: процессы, сеть, cron и таймеры, SUID,
`ld.so.preload`, ключи SSH, автозапуск оболочек, свежие изменения в системных каталогах.
Все команды только читают.

Если разбираете подозрение на взлом - не перезагружайте машину и ничего не удаляйте,
пока не сняли срез. После перезагрузки процессы и открытые соединения пропадут.

В архиве будут секреты: адреса, имена хостов, публичные ключи, история команд.
Прежде чем показывать его кому-то, откройте и вычистите.

Полезно снять такой срез на здоровой машине и положить в бэкап. Через полгода это
эталон, с которым можно сравнить, а половина работы при разборе уходит именно
на вопрос "так было всегда или нет".
